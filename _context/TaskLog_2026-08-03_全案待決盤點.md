### B14.（2026-08-14）請假判定漏接「時數範圍」型主旨 — 已產出修正包，待匯入實跑 [Claude@Win]

**症狀**：2026-08-14 林軒請假，1000 流程沒把 field_8 寫進清單（列 ID 1769 空白）；同日林寬祐同樣是請假卻寫進去了。

**根因（讀 `1000_清單__米米信代發解析_v2_0814_20260814022953.zip` 的 definition 逐字確認，非推測）**：`套用至每一個 → FilterEvents` 的第二段條件只認三種情況——主旨含字面 `10:00`、含 `全天`、事件跨日超過 1 天。林軒的主旨是 `林軒請年假，2026-08-14(09:00-18:00)…`：

| 判斷 | 結果 |
|---|---|
| 含 `10:00` | ✗ 只有 `09:00-18:00`，字串不含 `10:00` |
| 含 `全天` | ✗ |
| 跨日 >1 天 | ✗ start `08-14T00:00`、end `08-15T00:00` 恰好＝1 天，`greater(1,1)`＝false |

三者皆假 → FilterEvents 空 → 走分支 C 不動。**差別只在請假系統把時數寫成範圍還是「全天」**，事件層資料是對的。

**`isAllDay` 不可當判準（實測否決）**：林軒 `(09:00-18:00)` 與林寬祐 `(全天)` 的 `isAllDay` 都是 `true`——請假系統把所有假都建成全天事件，時數只寫在主旨裡。若拿 `isAllDay` 當「涵蓋整天」，下午假（如 `13:00-18:00`）會被誤判成請假、蓋掉當事人自己的米米信。**唯一可靠的來源是主旨括號內的時段字串。**

**修法**：把「含字面 `10:00`」換成「解析括號內時段，判斷是否涵蓋 10:00」——
