表單回覆 10:00 後唯讀 — ScrToday 變更

2026-06-22 ｜ Claude@Mac（ai-team：Codex 驗收）｜ 一般同事 10:00 後不能改回覆，只有行政可改
需求：回覆狀態的填寫截止在「今天 10:00」（與表單題目「請確認後於今天『10點前』回覆狀態」一致）。10:00 後一般同事的回覆唯讀，只有行政人員仍可修改。

0. 改三個地方（都在 ScrToday）

#控件 / 屬性做什麼
1Screen ScrToday.OnVisible多存一個 locIsAdmin 變數（判是否行政）
2radReply.DisplayMode10:00 後且非行政 → 唯讀（View）
3btnSubmit.DisplayMode ＋ OnSelect同條件鎖送出，且 OnSelect 內再自衛一次

1. ScrToday.OnVisible（畫面屬性，手動設）

原本：UpdateContext({locShowPopup: false}) → 改成多帶 locIsAdmin：

UpdateContext({
    locShowPopup: false,
    locIsAdmin: !IsBlank(LookUp(team_member, Email = User().Email, '出勤存取權限'))
})

行政判定與 btnAdmin.Visible 同一條件；存成變數後 DisplayMode 不必每次重算 LookUp（Codex 建議）。

2. radReply.DisplayMode

=If(locIsAdmin Or Hour(Now()) < 10, DisplayMode.Edit, DisplayMode.View)
  • Hour(Now()) < 10＝今天 10:00:00 前可編、10:00 起唯讀。
  • 行政（locIsAdmin）不受時間限制，恆可編。
  • DisplayMode.View＝顯示但不可改（比 Disabled 乾淨）。

3. btnSubmit：DisplayMode ＋ OnSelect 自衛

DisplayMode（同 radReply）

=If(locIsAdmin Or Hour(Now()) < 10, DisplayMode.Edit, DisplayMode.View)

OnSelect（在原 Patch 外包一層時間/行政判斷）

=If(
    !(locIsAdmin Or Hour(Now()) < 10),
    Notify("10:00 後僅行政人員可修改回覆", NotificationType.Error),
    Patch(AttendanceHistory, locSelected, {'表單回覆': radReply.Selected.Value});
    If(
        IsEmpty(Errors(AttendanceHistory, locSelected)),
        Notify("已送出回覆", NotificationType.Success);
        UpdateContext({locShowPopup: false}),
        Notify("送出失敗：" & First(Errors(AttendanceHistory, locSelected)).Message, NotificationType.Error)
    )
)
為何 OnSelect 也要判一次：DisplayMode 只擋畫面外觀，Patch 若被其他入口或殘留狀態觸發仍會寫入。把同一條件加在 OnSelect 內，雙保險（Codex F 指出）。

4. 重要：這是「畫面政策鎖」，不是硬安全

DisplayMode／Visible 都是前端 UI 層，不是安全邊界（專案 lessons 已記）。技術上有能力的人仍可能繞過 UI 直接寫清單。

  • 務實結論：對內部一般同事，UI 鎖即足夠政策效果。
  • 若要真正硬保障「10:00 後一般同事不可寫 field_7」：成本較高，做法是把寫入改走受控的 Power Automate／API、由流程用伺服器時間判斷並拒絕一般同事；或把清單權限設成一般同事不可直接編輯、只能透過受控流程寫。是否要做請 PO 評估（非本次必做）。
  • Hour(Now()) 取裝置本地時間；裝置時間被改會影響 UI 鎖（台灣內部使用可接受）。要嚴謹同樣得靠伺服器時間判斷。

5. 測試

  1. 一般同事帳號、10:00 前開卡片：可選回覆、可送出。
  2. 一般同事帳號、10:00 後：radReply 唯讀、btnSubmit 灰掉；若仍觸發送出 → 跳「10:00 後僅行政人員可修改回覆」。
  3. 行政帳號（team_member 有「出勤存取權限」）：任何時間都可改、可送出。
