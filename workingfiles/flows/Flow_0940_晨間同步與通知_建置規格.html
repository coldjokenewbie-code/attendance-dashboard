3. 動作

3-1　今日字串

Compose 今日DateString：
formatDateTime(convertFromUtc(utcNow(),'Taipei Standard Time'),'yyyy/M/d')
Compose 今日yyyymmdd：
formatDateTime(convertFromUtc(utcNow(),'Taipei Standard Time'),'yyyyMMdd')

3-2　讀來源

Excel 列出資料列 ×2：team_member（全體）、TaskDB（今日延遲列）。
TaskDB 篩今日：篩選查詢用日期欄，或全讀後於下一步用 startsWith(ID, 今日yyyymmdd) 過濾。（篩選行為未驗證，附 fallback：全讀＋條件）

3-3　段 A：延遲者每任務 upsert（來自 TaskDB）

對 TaskDB 今日列 Apply to each：
  1. Filter array 從 team_member 取該 Email 的 員工編號。
  2. 取得項目 AttendanceHistory，篩 RowKey eq 當前列 ID。
  3. 條件 有→更新項目，無→建立項目（欄位對應見下）。

3-4　段 B：未延遲者補占位列（來自 team_member）

對 team_member 全體 Apply to each：
  1. Filter array：TaskDB 今日列中該 Email 的任務數。
  2. 條件 length(...) = 0（今日無延遲任務）→
    • RowKey＝concat(今日yyyymmdd,'_',Email)（無任務 ID）。
    • 取得項目比對 → upsert 一列：方案名稱／任務名稱／表單回覆 留空，DateString＝今日、姓名／Email／員工編號＝team_member。

結果：清單＝全體本日各列；延遲者每任務一列、未延遲者一列占位。員工儀表板 Filter 自己 Email 即看到本日狀態（占位列顯示「（無延遲工作）」）。

3-5　發 Line（既有鏈路，Power Automate 不做）

發 Line 由既有 Planner2Line（Windows 桌機程式）負責，已運作：監聽 Outlook「工作延遲_人名 | MM/DD」通知信 → 清理正文（自動縮網址）→ 依 contacts.json（Email→LINE 聯絡人名稱）透過 LINE Desktop 發送。訊息模板：⚠️ 工作延遲通知 / 人員 / 日期 / 詳細內容{body}，連結來自郵件正文。

本 Power Automate 流程不發 Line，因此段 A/B 同步不受 9:45 窗口約束（但建議同步先於發 Line，員工點連結時清單已就緒）。

要讓 Line 帶「Power App 儀表板連結」：改上游延遲通知郵件正文的連結為儀表板 web 連結即可（Planner2Line 自動縮網址轉發；Power App 以登入者 Email 過濾，同一連結全員通用，不需 Forms 式超長預填）。Planner2Line 本身不用改。

4. 測試

  1. TaskDB 放今日測試列、team_member 有對應人 → 執行流程。
  2. 清單確認：延遲者每任務一列（RowKey＝ID）、未延遲者占位列、員工編號有查到。
  3. 重跑 → 確認 upsert 不重複。
  4. 段 C 連接器就緒後測 Line 收到連結。
  5. 全程計時確認 09:40 起 5 分鐘內可完成（人數多時觀察是否逼近上限）。
