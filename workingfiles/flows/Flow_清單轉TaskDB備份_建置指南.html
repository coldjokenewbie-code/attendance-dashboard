本日清單 → TaskDB 備份 建置指南

2026-06-26 ｜ Claude@Mac ｜ 手動觸發：把 SharePoint 清單 AttendanceHistory 的「今日」列，append 寫入 TaskDB.xlsx 的 TaskDB 表
三個決策（已拍板）：① 寫法＝append 累積、不清空（TaskDB 持續長大）。② 觸發＝手動按鈕（即時雲端流程）。③ TaskDB 有但清單沒有的 3 欄（Line 顯示名稱、到期日、狀態）一律留空。
平台鐵則（沿用前案踩坑）：① 所有運算式都用 fx 插入成紫色 chip，不要在欄位直接打字（否則被當字面字串、不計算）。② 此清單中文欄的內部名是 field_N，運算式一律用內部名：field_2 日期／field_3 Email／field_4 姓名／field_5 方案名稱／field_6 任務名稱／field_7 表單回覆／field_8 實際出勤狀態；唯一鍵欄維持 Title。③ 時區用 addHours(utcNow(),8)，不碰 convertFromUtc（此環境時區 ID 會報無效）。

逐步建置

步驟 0：建立流程

Power Automate → 建立 → 即時雲端流程 → 選 手動觸發流程（Manually trigger a flow） → 命名「清單轉TaskDB備份」。

步驟 1：Compose_今日篩選（產出 OData 篩選字串）

新增動作 Compose（撰寫），命名 Compose_今日篩選，輸入用 fx 貼整段： 
concat('startswith(Title,''',formatDateTime(addHours(utcNow(),8),'yyyyMMdd'),'_'')')

產出像 startswith(Title,'20260626_') 這樣的純字串。

為何先 Compose 再引用：$filter 欄直接打運算式會被當字面、巢狀單引號又會被截壞（前案踩過）。先 Compose 成完整字串、再把 Compose 的輸出整個丟進篩選查詢，最穩。expression 內嵌單引號用兩個 '' 表示一個。

步驟 2：取得清單項目

新增 SharePoint → 取得項目（Get items）：
  • 網站位址：選 AttendanceHistory 所在站台。
  • 清單名稱：AttendanceHistory。
  • 篩選查詢（Filter Query）：點欄位 → 動態內容 → 插入 Compose_今日篩選 的輸出（整個 token，不要自己打字）。
  • 展開「進階選項」→ Top Count 設 5000，並把分頁（Pagination）開、上限 5000，避免漏列。
驗證：先單獨測這步，看輸出 value 是否只含今日列、且筆數合理。空白＝今日前綴對不上（檢查 Compose 字串／是否真有今日資料）。

步驟 3：套用至每一個 → 將列新增至資料表

新增 套用至每一個（Apply to each），來源選 取得項目 的 value。迴圈內新增 Excel Online (Business) → 將列新增至資料表（Add a row into a table）：
  • 位置 / 文件庫 / 檔案：選 TaskDB.xlsx 所在站台（TEST_PLANNER_CK）與文件庫、檔案。
  • 表格：TaskDB。
  • 選完表格後會列出 11 個欄位，逐欄用 fx 貼上方對應表的運算式；Line 顯示名稱、到期日、狀態 三欄空著不填。
注意：運算式裡的 item() 指「當前迴圈的清單項目」，務必在 Apply to each 內插入；別用 items('套用至每一個')?['field_x'] 的長式（同義，但 item() 較短不易錯）。

重跑會重複 — 防呆（可選）

你選的是 append 不清空：同一天手動跑兩次，TaskDB 會出現兩份今日資料。三種處置擇一：
  1. 紀律法（最簡單）：約定「每天只手動跑一次」，跑完即停。
  2. 跑前手動清：執行前先到 TaskDB.xlsx 手動刪掉今日（ID 以今日 yyyyMMdd_ 開頭）的舊列，再跑。
  3. 流程內去重（要我加再說）：迴圈內 Add row 前先「列出資料表中的列」TaskDB、用 ID 比對當前 Title，已存在就跳過。會多一次 Excel 讀取／列、速度較慢，目前未建。

備註

  • 檢核日期格式：清單 日期 是文字 2026/3/2（無補零），原樣寫入 TaskDB；若 TaskDB 該欄是日期格式可能存成文字，備份用途可接受，要嚴格日期型再議。
  • WeekDB / MonthDB：本流程只寫 TaskDB。若既有彙整鏈路靠 TaskDB 往上捲，append 模式下 TaskDB 已含多天資料，捲動邏輯需另確認（本案未動）。
  • 站台確認：TaskDB.xlsx 實際在 TEST_PLANNER_CK（test 即正式在用）；以連接器實選為準。
