請假整合 — 全流程建置指南

2026-07-06 ｜ Claude@Win ｜ 需求源：workingfiles/0706.txt（PO 已確認 A1/2/3、B）。目的：當天請假者自動標記、且各延遲通知/提醒一律排除，不再打擾已請假的人。
一句話：0945 加行事曆判定「當天請假」→ 對其延遲列寫 表單回覆 field_7 = 4. 延遲（09:30沒到公司，當天已請假） 並不寄延遲信；下游 0955 發卡、1005/1030 提醒一律排除請假者。實際出勤狀態 field_8=「請假」維持由 1000 米米信流程寫，兩欄不衝突。

0. 資料欄位與判定約定

  • field_7＝表單回覆（員工填 / 0945 / 0955 寫）；field_8＝實際出勤狀態（1000 米米信寫，請假寫「請假」）。
  • 員工回覆選項（已更新為 5 項）：1.已完成／2.延遲(已到補進度)／3.延遲(沒到·填假卡)／4.延遲(沒到·當天已請假)／5.其他(5分內改卡)。
  • 「仍延遲」判定＝最終 field_7 以 3. 開頭（0955 據此發卡）。請假者 field_7=4.→非 3.→天然不發卡。
  • 行事曆判請假沿用 1000 米米信現行技術（主旨含姓名＋當天日期＋10:00/全天）。
模式與右值填法（全指南通則，務必照做）
  • 篩選陣列（Filter array）有兩種模式：基本模式＝左值/運算子/右值三格；進階模式＝單一 @布林運算式 一格。本指南每處都標明用哪個。（右上「⋯ → 編輯進階模式」可切換）
  • 條件（Condition）新版只有基本模式（左/運算子/右三格），沒有進階模式——複雜布林要塞左值 fx。
  • 右值鐵律：布林（true/false）與數字比較，右值一律 fx 插入 token（直接打字會變字串 → equals(布林/數字,'字串') 永遠 false）；純字串字面值（如 Y）可直接在格子打字。
  • 凡是「fx」＝在該格點 fx 圖示插入成彩色 token，不是直接打字（灰字＝字面、彩 chip＝運算式）。

動作位置總覽（綠＝新增、藍＝改）：

（迴圈外）
  … 列出表格中的列_名冊 (Excel)
  … 延遲列（原有取清單延遲列的動作）
＋ 取得行事曆_請假 (V3)              ← §2-1（放 apply_to_each_mail 之前）

apply_to_each_mail   ← foreach 名冊
  ├ 篩選_延遲任務數量               （原有）

  ├＋ Compose 本人請假              ← §2-2②
  ├ 條件_要寄嗎  （§2-3 改左值加 not(outputs('本人請假')))

2-1　迴圈外：取當天行事曆一次 新增

在 apply_to_each_mail 之前加「取得行事曆檢視的事件 (V3)」，命名 取得行事曆_請假，行事曆選 domain.e 信箱（同 1000）。時間範圍（fx 插入）：

開始時間concat(formatDateTime(convertFromUtc(utcNow(),'Taipei Standard Time'),'yyyy-MM-dd'),'T00:00:00+08:00')
結束時間concat(formatDateTime(convertFromUtc(utcNow(),'Taipei Standard Time'),'yyyy-MM-dd'),'T23:59:59+08:00')

只取今天單日（台北 00:00–23:59），不加寬，避免全天事件 UTC 邊界誤撈昨天的假（同 1000 的理由）。

2-2　迴圈內：判本人是否當天請假 新增

在 Compose_任務數量 之後加：

① 篩選陣列 FilterEvents_本人請假（進階模式）：加「篩選陣列」後，點右上 ⋯ → 編輯進階模式，where 變成單一 @布林 一格。

來源 From@body('取得行事曆_請假')?['value']
where（進階模式一格，整段貼）@and(contains(split(item()?['subject'],'代理')[0], items('apply_to_each_mail')?['姓名']), contains(item()?['subject'], formatDateTime(convertFromUtc(utcNow(),'Taipei Standard Time'),'yyyy-MM-dd')), or(contains(replace(item()?['subject'],'：',':'),'10:00'), contains(item()?['subject'],'全天')))

與 1000 的 FilterEvents 同義（1000 用基本模式 if(...)='Y'，此處改進階 @and(...) 較簡潔、兩者等效）；姓名用本流程名冊 items('apply_to_each_mail')?['姓名']（1000 用 field_4）。半/全形冒號先 replace('：',':') 再比。

② Compose 本人請假（輸入框切 fx 貼）：@greater(length(body('FilterEvents_本人請假')),0)

2-3　排除寄信：改「要寄嗎」條件 改

把既有「要寄嗎」條件左值（原 and(greater(length(body('篩選_延遲任務數量')),0), not(empty(...Email...)))）加一項 not(outputs('本人請假'))：

and(
  greater(length(body('篩選_延遲任務數量')),0),
  not(empty(trim(string(coalesce(items('apply_to_each_mail')?['Email'],''))))),
  not(outputs('本人請假'))
)

運算子＝等於、右值＝fx 插入 true（不可直接打字，否則變字串永遠 false）。請假者→左值 false→不進「是」分支→不寄信。

2-4　對請假者的延遲列寫 field_7=4 新增

位置：在 apply_to_each_mail 迴圈內，緊接在 條件_要寄嗎 這個條件的下面（同一層、runAfter＝條件_要寄嗎 成功）。在此新增一個「條件」條件_請假需標記（基本模式，左/運算子/右三格），左值切 fx 貼：

and(outputs('本人請假'), greater(length(body('篩選_延遲任務數量')),0))

運算子＝等於、右值＝fx true。「是」分支內加巢狀迴圈 apply_to_each_請假列（來源 @body('篩選_延遲任務數量')）→ 內放「更新項目」更新項目_標記請假（站台/清單同流程）：

識別碼 ID@items('apply_to_each_請假列')?['ID']
標題 Title@items('apply_to_each_請假列')?['Title']
表單回覆 field_74. 延遲（09:30沒到公司，當天已請假）（直接字面字串即可，非運算式）

順序注意：`篩選_延遲任務數量` 的來源是「延遲列」（清單物件，含 ID/Title），故可逐列更新。此段與 §2-3「不寄信」互不衝突：請假者兩件事都做——標 field_7=4、且不寄信。

3. 0955 再巡檢/發卡：收斂改 1或5＋排除請假 改

檔：Flow_0955_新增發卡提醒_建置指南.html 對應流程。

3-1　收斂範圍 1或4 → 1或5 改

在 Apply_to_each_列 迴圈內找 Compose 動作 本列原勾選1或4。它現在的內容是（已從你 0630 匯出確認一字不差）：

@or(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'1.'),startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'4.'))

唯一要做的：把結尾那個 '4.' 改成 '5.'。改完整段為：

@or(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'1.'),startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'5.'))

理由：新選項 4＝請假（比照 2/3 保留不動），5＝其他（要重掃收斂）。改完收斂只作用在「已完成(1)／其他(5)」。動作可不必更名，內容改掉即生效。

再找同迴圈的 Compose 本列未回覆，現在是：

@and(not(startsWith(…,'1.')),not(startsWith(…,'2.')),not(startsWith(…,'3.')),not(startsWith(…,'4.')),not(startsWith(…,'原勾選')))

在中間插一條 not(startsWith(…,'5.'))（否則選「5.其他」會被誤當未回覆）。完整貼上版：

@and(not(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'1.')),not(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'2.')),not(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'3.')),not(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'4.')),not(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'5.')),not(startsWith(trim(coalesce(items('Apply_to_each_列')?['field_7'],'')),'原勾選')))

改寫用的 更新項目_卡片仍延遲 完全不用動——它是 @concat('3. 延遲（09:30沒到公司，請填寫假卡）（原勾選「', trim(coalesce(items('Apply_to_each_列')?['field_7'],'')), '」，卡片仍延遲）')，動態讀 field_7，選項改號不受影響。你這版沒有「已退出逾期」的更新動作（該分支目前為空），也不用管。

3-2　發卡排除請假者 改

請假者 field_7=4.→非 3.→本就不在「仍延遲」→天然不發卡。為保險（防某人 field_8=請假 但 field_7 仍 3.），把 仍延遲_篩選陣列（進階模式，原本就是 @startsWith(...,'3.')）的 where 整段換成：

@and(
  startsWith(trim(coalesce(item()?['field_7'],'')),'3.'),
  not(startsWith(coalesce(item()?['field_8'],''),'請假'))
)

4. 1005/1030 米米信未回報提醒：排除請假 改

檔：Flow_1005_1030_米米信未回報提醒_建置指南.html。現況已靠 field_8 非空自動排除請假（1000 寫「請假」進 field_8→算已回報）。加固：把 已回報列 篩選陣列（進階模式，原 @not(empty(item()?['field_8']))）的 where 改成（涵蓋 0945 剛標的 field_7=4.，防 1000 尚未跑）：

@or(
  not(empty(trim(coalesce(item()?['field_8'],'')))),
  startsWith(coalesce(item()?['field_7'],''),'4.')
)

field_7 以 4. 開頭（＝當天已請假）或 field_8 已有值＝視為已回報 → 不列入提醒名單。

5. 1000 工作延遲彙整→行政 email：排除請假 改

流程 1000工作延遲彙整_通知行政email（週一~五 10:00）：讀 Excel TaskDB.xlsx，逐「有延遲的人」寄彙整信給行政 domain.e。此流程以 Excel 欄「姓名/Email」為鍵，無 field_7/field_8，故排除請假要靠行事曆判定＋條件擋信。

現況結構：列出表格中的列(Excel GetItems) → 未回覆_篩選陣列(where @not(empty(item()?['姓名']))) → 選取(Email) → UniMail_Compose(@union去重) → Apply_to_Each_Mail{ 篩選_延遲任務(該人) → 選取_任務明細 → 聯結_任務明細 → 傳送電子郵件_(V2)(To domain.e) → 延遲(Wait 15s) }。

在 Apply_to_Each_Mail 之前（例如 UniMail_Compose 之後）加「取得行事曆檢視的事件 (V3)」取得行事曆_請假，行事曆選 domain.e，時間範圍（fx 插入，今天台北 00:00–23:59）：

5-2　迴圈內：判本人請假 新增

在 篩選_延遲任務 之後加篩選陣列 FilterEvents_本人請假，From @body('取得行事曆_請假')?['value']，進階模式 where：

@and(
  contains(split(item()?['subject'],'代理')[0], first(body('篩選_延遲任務'))?['姓名']),
  contains(item()?['subject'], formatDateTime(convertFromUtc(utcNow(),'Taipei Standard Time'),'yyyy-MM-dd')),
  or(contains(replace(item()?['subject'],'：',':'),'10:00'), contains(item()?['subject'],'全天'))
)

此流程無 field_4，姓名改取該人第一筆延遲列 first(body('篩選_延遲任務'))?['姓名']（Excel 欄名「姓名」）。

5-3　條件擋住請假者寄信 改

加條件 條件_未請假才寄（基本模式，條件無進階模式）：左值切 fx @empty(body('FilterEvents_本人請假'))、運算子 等於、右值切 fx 插入 true（布林一律 fx，直接打字變字串永遠 false）。把既有 選取_任務明細 / 聯結_任務明細 / 傳送電子郵件_(V2) 三個 action 移進「是」（＝未請假）分支；「否」分支留空。延遲(Wait) 留在迴圈末不動。

效果：請假者 → FilterEvents>0 → 條件否 → 不寄彙整信給行政。（邊角：若當天延遲者全部請假，行政不會收到人別信，也不會觸發「無人延遲」信——那支是看 選取 筆數；可接受。）

  1. ScrToday 貼上（5 選項）→ 手機測回覆彈窗第 4「請假」可選、送出寫入 field_7=4. …當天已請假。
  2. 0945：加 §2 各 action → 測「當天有請假事件的人」→ (a) 其延遲列 field_7 被寫 4. …、(b) 不在收信對象（收件者仍固定 domain.e，但該人不觸發寄信邏輯）。
  3. 0955：改 §3 →「原勾選 5(其他)仍逾期」才收斂發卡；「原勾選 4(請假)」保留不動、不發卡。
  4. 1000工作延遲彙整→行政 email：加 §5 → 請假者不寄行政彙整信給行政。
  5. 1005/1030：改 §4 → field_7=4. 或 field_8 有值者不被提醒。

回歸重點：確認請假者不會被打擾——0945 延遲信、0955 發新卡、1005/1030 米米信提醒皆跳過，行政也不會收到其 1000 延遲彙整信；且行政頁看得到其 field_7=4. …當天已請假（清單仍保留該列）。
