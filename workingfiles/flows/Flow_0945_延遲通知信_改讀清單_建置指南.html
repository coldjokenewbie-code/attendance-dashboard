三條鐵則（先記）
① 所有運算式都要切「進階模式 / 切換到輸入整個陣列」或點 fx插成彩色 chip，不可直接打字（灰字＝被當字面字串，必失敗）。
② SharePoint 清單中文欄的內部名是 field_N：field_3＝Email、field_4＝姓名；Excel 名冊欄是原 header：Email、姓名（不是 field_N）。
③ 寄信 收件者 To 永遠是 domain.e@techartgroup.com（中繼信箱）。逐人路由是 Planner2Line 讀主旨的姓名對 contacts.json 轉發 LINE，不靠 To。別把 To 改成個人 Email。

0. 你現在卡的：篩選_延遲任務數量「一直出問題」

病灶：這條 where 只有在 apply_to_each_mail 的 foreach 已經改成跑 Excel 名冊時才成立。若 foreach 還停在舊的 UniqueEmails（字串陣列），迴圈值是字串，對它取 ?['Email']／?['field_3'] 會直接失敗。
所以單改這條沒用——必須照下面 §3 的順序整段改（先加 Excel 名冊＋改 foreach，再改這條 where）。改完的最終正確形： 
@equals(
  toLower(trim(string(coalesce(item()?['field_3'],'')))),
  toLower(trim(string(coalesce(items('apply_to_each_mail')?['Email'],''))))
)
左側 item()?['field_3']＝正在被篩的「延遲列」那筆的 Email；右側 items('apply_to_each_mail')?['Email']＝目前迴圈到的名冊那個人的 Email。用 string(coalesce(...,'')) 防 null／型別。

1. 為什麼舊版會壞（要砍掉的）

  • 壞選取(Select)：select{Email: toLower(item()?['Email'])} —— 清單內部名是 field_3，用 Email 映出 null；UniqueEmails 去重後剩一個 null，迴圈只跑一次。
  • 壞篩選_延遲任務數量 的 where 還寫死 equals(item()?['field_3'],'ihueychen@techartgroup.com')（除錯殘留，根本沒用迴圈值）。
  • 定案：棄用 Select 去重，改用 team_member(Excel) 名冊跑迴圈（結構穩定、不再有字串/物件型別漂移）。

3. 逐步就地編輯（照順序，別跳）

A新增 Excel「列出表格中的列_名冊」

  1. 在 延遲列 之後加一個 Excel Online (Business) → 列出表格中的列，改名 列出表格中的列_名冊。
  2. 從 designer 加（會自動建/選 Excel 連線參照）——不要手編 JSON，否則少了 connectionReference 存檔會失敗。可直接用原始版那個 Excel 連線。
  3. 位置：檔案＝TaskDB.xlsx（原始版讀的同一檔）；表格＝team_member（從下拉選，不是 TaskDB 那個逾期表）。
  4. 不要設 $filter（要讀全體名冊）。
  5. 展開「⋯ → 設定」把 分頁(Pagination) 開啟、門檻拉到 ≥ 名冊人數（預設常只拿 256 筆，名冊超過會漏寄）。

team_member 表的 header 必須精確是 姓名、Email（已對過 CSV，無尾空白）。若 Excel 實際欄名有空白／E-mail／Name 之類，後面取值會是空——存檔前先用一次「測試→看該動作原始輸出」確認 key。

B刪掉 選取、UniqueEmails

兩個都刪。刪 UniqueEmails 後 apply_to_each_mail 會少了 foreach 來源，下一步補上。

C改 apply_to_each_mail 的 foreach 來源

foreach 改成（fx token）：

@body('列出表格中的列_名冊')?['value']

現在迴圈值＝名冊一個人（物件），欄走 Excel header：items('apply_to_each_mail')?['姓名']、?['Email']。

D改 篩選_延遲任務數量 的 where（就是你卡的那條）

來源 From 維持 @body('延遲列')；切進階模式，where 整段貼（fx token）：

@equals(toLower(trim(string(coalesce(item()?['field_3'],'')))), toLower(trim(string(coalesce(items('apply_to_each_mail')?['Email'],'')))))

Compose_任務數量 不動：@length(body('篩選_延遲任務數量'))。

E新增 條件「要寄嗎」，把 傳送/延遲 移進 True

  1. 在 Compose_任務數量 之後加一個 條件 Condition，改名 要寄嗎。
    條件卡沒有「進階模式」（新版 designer 拿掉了，那是「篩選陣列」才有）。複雜布林運算式要塞進左值，再跟 true 比：
    • 左值：點左格 → fx/運算式 → 貼（不含開頭 @）：
      and(greater(length(body('篩選_延遲任務數量')),0), not(empty(trim(string(coalesce(items('apply_to_each_mail')?['Email'],''))))))
    • 運算子：等於
    • 右值：務必用 fx 打 true（boolean）。不可直接在格子打 true —— 會變字串 'true'，equals(布林,'true') 永遠 false、永遠不寄。
    件數>0、且名冊這列 Email 非空才走 True。
  2. 把 傳送電子郵件_(V2) 與 延遲 拖進 True 分支。
  3. runAfter 一定要重接（分支內 action 只能接同分支 sibling）：True 內 傳送電子郵件_(V2) 是第一個（runAfter 空）、延遲 接在傳送之後。條件 要寄嗎 本身接在 Compose_任務數量 之後。False 分支留空。

4. 主旨／姓名為何用名冊（不是清單 field_4）

Planner2Line 靠主旨的姓名對 contacts.json 找 LINE 對象。名冊(team_member)的姓名是權威來源；清單 field_4 是任務歷史列，可能舊名/錯字/不同步。用名冊姓名 → 與 contacts.json 對得上。新人記得先加進 contacts.json。

5. 實跑前檢查清單（Codex 點出的地雷）

檢查說明
Excel 分頁開了嗎名冊 > 256 列不開分頁會漏人。
Excel header 精確姓名/Email 不能有空白/全形/E-mail；測試看原始輸出 key。
To = domain.e逐人靠主旨路由，To 不可改個人信箱。
寄件連線白名單傳送郵件 V2 的連線帳號要是 domain.e 或 ihueychen（否則 Planner2Line 略過），且不被 DLP／外部收件限制擋。
主旨姓名別空名冊那列 姓名 空 → 寄出 工作延遲_ | MM/dd，Planner2Line 對不到人。名冊維護好即可。
SharePoint Title 索引startswith(Title,…) 委派；Title 有索引較穩。Top 5000 對單日量足夠。
空清單日延遲列空、名冊照跑、件數全 0 不寄 —— 正常。

  3. 到 domain.e 信箱看：有延遲的人每人一封、主旨 工作延遲_姓名 | MM/dd、內文含件數＋儀表板連結；沒延遲者不寄；占位列不寄。

附錄（可選）名冊缺漏告警 — 待 PO 裁示

風險：名冊版只寄「在 team_member 名冊裡」的人。若某人在延遲清單、卻不在名冊（臨時人員／離職未同步／0930 join 失敗），會漏寄且無人察覺。Codex 評估此 regression 中偏高。

建議的輕量防線（只偵測、發一封告警，不做逐人 fallback，避免把複雜度帶回來）：

  1. 主迴圈後，初始化陣列變數 缺漏清單 = []。
  2. apply_to_each_2 跑 @body('延遲列')：
    • 篩選陣列 在名冊嗎：來源 @body('列出表格中的列_名冊')?['value']；where @equals(toLower(trim(string(coalesce(item()?['Email'],'')))), toLower(trim(string(coalesce(items('apply_to_each_2')?['field_3'],'')))))
    • 條件 @equals(length(body('在名冊嗎')),0) → True：附加至 缺漏清單，值 @concat(coalesce(items('apply_to_each_2')?['field_4'],''),' <',coalesce(items('apply_to_each_2')?['field_3'],''),'>')
  3. 迴圈外條件 @greater(length(variables('缺漏清單')),0) → 寄一封告警到 domain.e：
    • 主旨 0945排程告警_名冊缺漏 | @{formatDateTime(addHours(utcNow(),8),'MM/dd')}
      主旨絕不能用 工作延遲_ 開頭——否則 Planner2Line 會把「名冊缺漏」當人去 contacts.json 找、發錯。
    • 內文 @join(variables('缺漏清單'),'<br>')

全程只用 篩選陣列＋附加陣列變數＋join，沒有 Select Map，不會踩原本的型別坑。內層 Filter 來源是記憶體中的名冊輸出、不是重抓 Excel。同一缺漏者多筆任務會重複列（要去重可在附加前加 not(contains(...))）。
