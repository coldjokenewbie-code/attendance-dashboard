2026-06-22 ｜ Claude@Mac ｜ 在既有「0945每日專案延誤通知EMAIL」上改：來源 Excel→SharePoint 清單、連結改儀表板
核心觀念：① 所有運算式都用 fx 插入成紫色 chip，不要直接打字（否則被當字串）。② 此清單中文欄的內部名是 field_N，運算式要用內部名：field_1 員工編號／field_2 日期／field_3 Email／field_4 姓名／field_5 方案名稱／field_6 任務名稱。Title 維持 Title。
現況（不用重建，只改 3 處）：觸發 09:45 → 列出表格中的列(Excel 今日) → 選取(Email) → UniqueEmails(union 去重) → apply_to_each_mail{ 篩本人列、算件數、組任務明細(Forms連結)、寄信到 domain.e、等10秒 }。
要改：① 來源 Excel→清單　② 下游改引用 body('延遲列')　③ 連結 Forms→儀表板。

1. 換來源：列出表格中的列(Excel) → 取得項目(SharePoint)

  1. 刪掉 列出表格中的列（Excel）。
  2. 加 SharePoint → 取得項目 取得清單項目：站台 PLANNER_CK、清單 AttendanceHistory。
  3. 篩選查詢：清空 → 點 fx(運算式) → 貼下面一整段 → 確定（變成紫色 chip，欄位裡不要再打任何字）：
    concat('startswith(Title,''', formatDateTime(addHours(utcNow(),8),'yyyyMMdd'), '_'')')
    會算出 startswith(Title,'20260622_')（'' 是跳脫單引號）。Top Count 5000。
  4. 加 篩選陣列 延遲列：來源＝取得清單項目 的 value；條件（進階）：
    @not(endsWith(item()?['Title'],'_TaskOnSchedule'))　→ 去掉占位列，只留延遲列。

之後所有「逐列資料」都改引用 延遲列 的輸出（body('延遲列')），不要再用 Excel 那個。

2. 去重到人（選取 / UniqueEmails）

選取用「文字模式」（單框），對應(Map)貼的運算式要用 fx 插入成紫色 chip（直接打字會被當字串、報「請輸入有效的 JSON」）。
  • 選取(Select)：來源 From＝body('延遲列')；對應(Map, 文字模式)用 fx 插入：toLower(item()?['field_3'])（field_3＝Email）。輸出為字串陣列 ["a@x", …]。
  • UniqueEmails(Compose)：union(body('選取'), body('選取'))。

迴圈項是字串，後面引用 email 用 items('apply_to_each_mail')（不要加 ?['Email']）。

3. 逐人寄信（apply_to_each_mail 內）

  • 篩選_延遲任務數量(篩選陣列)：來源 body('延遲列')；切「進階模式」貼這段防呆版（不論 選取 是字串或物件模式都中；field_3＝Email）：
    @or(equals(toLower(trim(string(item()?['field_3']))), toLower(trim(string(items('apply_to_each_mail'))))), contains(toLower(replace(string(items('apply_to_each_mail')), ' ', '')), concat('"email":"', toLower(trim(string(item()?['field_3']))), '"')))
  • 前提：先確認 選取 的輸出是真 email（["ihueychen@…"] 或 [{"Email":"ihueychen@…"}]），不可是字面文字或 null；若是，對應(Map)用 fx 重插 toLower(item()?['field_3']) 成紫色 chip。
  • Compose_任務數量：length(body('篩選_延遲任務數量'))。
  • 刪掉 選取任務明細 與 聯結任務明細（不在信裡逐筆列任務，避開另一個文字模式 Select；任務明細交由儀表板顯示）。

4. 寄信動作（連結改儀表板）

傳送電子郵件 (V2)（主旨／內文用 fx 插入運算式，非純打字）：
欄填入
收件者 Todomain.e@techartgroup.com
主旨 Subject工作延遲_@{first(body('篩選_延遲任務數量'))?['field_4']} | @{formatDateTime(addHours(utcNow(),8),'MM/dd')}（field_4＝姓名）
內文 Body<p>@{first(body('篩選_延遲任務數量'))?['field_4']}，您今天有 @{outputs('Compose_任務數量')} 件延遲工作，請開啟出勤儀表板確認並回覆：<br>你的儀表板網址</p>

儀表板網址：填你 App 的 Web 連結（Power Apps → 該 App → 詳細資料 → Web 連結）。App 已用 User().Email 自動篩當事人，全員共用同一條連結即可，不需逐任務預填。Planner2Line 會從正文抽這條 URL、縮短後發到該員 LINE。

5. 寄件者與時序（不變）

  • 寄件者必須是白名單帳號：傳送電子郵件的 Office 365 連線要用 domain.e@techartgroup.com（或 ihueychen），否則 Planner2Line 會略過。
  • 主旨格式 工作延遲_姓名 | MM/dd 不能變；姓名 要與 contacts.json 對得上（去空白比對）；新人要先加進 contacts.json。
  • 每封間隔等 10 秒的 延遲(Wait) 保留，給 LINE Desktop 發送節奏。
  • 時間用 addHours(utcNow(),8)＝台北（你原本的 convertTimeZone(...,'Taipei Standard Time') 也可，二擇一即可）。

6. 測試

  1. 手動測試跑一次（先確認清單今天已有延遲列，可由 0930 寫入或手動建幾筆）。
  2. 到 domain.e 信箱看：每位延遲者一封信、主旨 工作延遲_姓名 | MM/dd、內文含任務清單＋儀表板連結。
  3. 占位列（無延遲者）不會收到信（已被 延遲列 濾掉）。
  4. Planner2Line 端：確認轉發到各人 LINE、連結可點開儀表板。
