## 2026-08-03 改造：巡檢不再改寫同事回覆

四支流程一起改，核心原則＝**系統只寫 `PlannerStatus`，不碰 `field_7`（表單回覆）**。

| 流程 | 改動 |
|---|---|
| 0945 | 移除 `條件_請假需標記` 整組——不再自動把請假者的 `field_7` 預填成「4.」、也不再寫 `field_8`（改由 1000 分支 A 於 10:00 寫入） |
| 0955 | 拆掉 `條件_1或5或空白`／`本列原勾選1或5`／`本列未回覆` 三段，改為對每列無條件寫 `PlannerStatus = if(本列狀態異動,'已更新','延遲')` |
| 1015 | 同 0955；另把「建立工作」（發 Planner 卡片）換成寄信，與 0955 統一走 LINE 轉發信箱 |
| 1030 | 資料源由 Excel 改為 SharePoint 清單＋上週一~週五區間篩選；統計基準統一為 `field_7` 前綴 `3.` |

**通知對象判定**（0955／1015 共用）：`PlannerStatus = '延遲'` 且 `field_7` 為 `1.`／`5.`／空白。勾 2、3、4 者不發。依 PO 裁示，請假者仍須填寫儀表板，故不排除請假者。

**1030 的統計基準用前綴 `3.` 而非全文比對**：清單既有資料存的是舊文字「請填寫假卡」，新選項改為「待填寫假卡」，全文比對會讓上週資料全數落空（舊版信二就是踩到這個坑，比對字串與實際值差一個空格而靜默歸零）。

**改什麼**：只動 `FilterEvents` 的 `where`，加兩條事件日期閘——
`起日 ≤ 台北今日` 且 `迄日 > 台北今日`。不新增動作、不動連線宣告。
